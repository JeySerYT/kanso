# Спека v0.4 — удаление, граф, структура, бренд, читаемость

Статус: согласована (решения пользователя зафиксированы ниже).
Предшественник: `docs/redesign.md` (v0.3, терминал-диспетчер).

## Problem Statement

1. Задачу нельзя удалить по-настоящему: DELETE отвечает 405, «удаление» — это статус canceled, мусорные задачи копятся навсегда.
2. Нет обзора связей между задачами: зависимости `blocked_by` видны только текстом в drawer, общую картину блокировок не увидеть.
3. Часть текста в CRT-теме читается плохо (низкий контраст вторичного текста, шум scanlines/grain поверх контента).
4. Логотип (иероглиф 簡) и фавикон не нравятся пользователю, знак не читается на 16px.
5. Вся логика доски лежит в одном файле (~1900 строк JS + ~2400 строк CSS), страница перегружена компонентами; graф нельзя добавлять туда же без further разрастания.

## Solution

- Настоящее удаление задачи с подтверждением: кнопка в drawer → диалог → задача исчезает из базы, ссылки у других задач чистятся, все вкладки обновляются через SSE.
- Новый вид «Граф» в стиле Obsidian: canvas force-layout, узлы-задачи, рёбра-зависимости; переключатель видов «Доска / Граф».
- Редактор зависимостей в drawer, чтобы граф можно было наполнять из UI.
- Код доски разбит на ES-модули по подпапкам, CSS — на тематические файлы; без сборщика.
- Новый знак: минимал-канбан glyph (три вертикальных штриха разной высоты в квадрате), единый для лого и фавикона.
- Точечный аудит и правка контраста/шума с сохранением CRT-стиля.

## User Stories

1. Как пользователь доски, я хочу удалить задачу навсегда через кнопку в drawer, чтобы мусор не копился в базе.
2. Как пользователь, я хочу видеть диалог подтверждения с названием задачи перед удалением, чтобы не удалить случайно.
3. Как пользователь, я хочу, чтобы чужая задача с активной арендой не удалялась, чтобы не ломать работу другой сессии.
4. Как пользователь, я хочу, чтобы после удаления задача исчезала из всех открытых вкладок без перезагрузки, чтобы видеть актуальную доску.
5. Как пользователь, я хочу, чтобы ссылки на удалённую задачу в `blocked_by` других задач убирались автоматически, чтобы не оставалось висячих блокировок.
6. Как пользователь, я хочу, чтобы задача, все блокировки которой сняты удалением, переезжала из backlog в todo, чтобы разблокированная работа была видна.

8. Как пользователь, я хочу получать понятную ошибку при удалении несуществующей или арендованной задачи, чтобы понимать, что произошло.
9. Как пользователь, я хочу открывать вид «Граф» переключателем в шапке, чтобы видеть карту задач и блокировок целиком.

## Implementation Decisions

### Удаление (бэкенд)
- Новый метод store `deleteTask(id, { session })`: одна транзакция; отказ `not_found`; отказ `leased`, если есть активная (непросроченная) аренда другой сессии; своя аренда снимается вместе с задачей.
- Каскады: claims и comments удаляются через существующие FK ON DELETE CASCADE. У threads нет FK на tasks: треды, ссылающиеся на задачу (task_a/task_b), удаляются явным запросом, сообщения за ними — через FK threads→messages.
- После удаления: из `blocked_by` всех задач убирается удалённый id; backlog-задачи без оставшихся блокировок переезжают в todo (правило совпадает с существующим unblockDependents).
- HTTP: `DELETE /api/tasks/:id` → 200 `{ ok: true, id }`; 404 `not_found`; 409 `leased`. Ответ 405 `use_canceled_status` убирается. SSE-событие `task.deleted` с `{ id }`.
- CLI: команда `delete <id> --yes`; без флага — ошибка с подсказкой. Тексты через i18n-ключи.

### Удаление (веб)
- Кнопка «Удалить» в drawer (danger-зона) → модальный диалог подтверждения с названием задачи → DELETE → drawer закрывается, информационный тост без undo (hard delete необратим, подтверждение — единственная защита).
- Команда удаления в палитре для текущей выбранной задачи.

### Зависимости
- PATCH уже принимает `blocked_by` — бэкенд не меняется, кроме валидации: store отклоняет self-reference и циклы (код `cycle`) при create/patch; проверка — обход графа зависимостей.
- Drawer: секция «Blocked by» — список текущих блокировок с кнопкой удаления и пикер задач (поиск по id/названию, исключая саму задачу). Сохранение через существующий PATCH.

### Граф
- Отдельный вид, переключатель «Доска / Граф» в шапке; состояние вида — в URL hash и localStorage.
- Canvas 2D, собственный force-layout (отталкивание узлов, пружины по рёбрам, центрирование), без зависимостей. Симуляция затухает и останавливается; при скрытой вкладке и reduced-motion — статичная раскладка.
- Узлы: цвет по статусу (существующая палитра), радиус по приоритету (p0 крупнее), зелёное кольцо при активной аренде. Рёбра: направленные, стрелка blocker → dependent.
- Взаимодействия: drag узла, пан фона, зум колесом/pinch, клик по узлу → drawer, hover → тултип (id, title, статус). Тач: тап = клик, один палец = пан/драг, два = pinch.
- Данные: существующий `/api/board` + SSE; фильтр проекта и поиск применяются к узлам. DPR-aware рендер.
- Пустые состояния: нет задач / нет связей — подсказки с i18n-ключами.

### Структура кода
- `web/board.js` → ES-модули в `web/js/`: точка входа `main.js`; `core` (состояние, API, тосты, хелперы), `board` (колонки и карточки), `drag`, `events` (SSE), `toolbar`, `drawer`, `compose`, `palette`, `hotkeys`, `language`; граф — отдельный `graph` в шаге 4. Нативный ESM, без сборщика; `index.html` грузит один entry-модуль.
- `web/board.css` → тематические файлы в `web/css/`: base, layout, buttons, toolbar, board, dialogs, drawer, overlays, feedback, responsive (+ `graph` в шаге 4), подключаются через `<link>` в порядке исходного каскада.
- Поведение не меняется; тестовые швы (store/conflicts/http/cli/git/i18n) не затрагиваются рефакторингом.

### Бренд
- Новый знак: три вертикальных штриха разной высоты (колонки канбана) в квадрате, SVG, цвет — акцент палитры. Один знак для лого в шапке и `favicon.svg`; читаемость на 16px обязательна. Иероглиф 簡 убирается.

### Читаемость
- Аудит контраста вторичного текста: основной текст ≥ 4.5:1, крупный/декоративный ≥ 3:1; правка приглушённых цветов токенами палитры, стиль CRT сохраняется.
- Scanlines/grain: снизить интенсивность поверх контентных зон; переключатель «Эффекты» (persist), выключенный режим полностью убирает слои.

### Локализация
- Все новые строки — ключами в `web/locales/ru.json` и `en.json`, паритет ловит существующий тест.

## Testing Decisions

- Тестируем только существующие швы из AGENTS.md, новых швов нет. Хороший тест проверяет внешнее поведение (коды, контракты, тексты), не внутренности.
- `test/store.test.js`: deleteTask — успех, not_found, отказ при чужой активной аренде, каскад comments/claims/threads, чистка blocked_by, разблокировка backlog→todo, отклонение self-reference и циклов.
- `test/http.test.js`: DELETE 200/404/409, SSE-кадр `task.deleted`, JSON-контракт.
- `test/cli.test.js`: `delete` требует `--yes`, тексты вывода/ошибок.
- `test/i18n.test.js`: паритет ключей (существующий).
- Граф, виды, удаление в UI, бренд, читаемость — проверка в браузере (Playwright-сценарии + ручной просмотр), как принято в проекте для UI.
- Prior art: существующие test/store.test.js, test/http.test.js, test/cli.test.js.

## Out of Scope

- Корзина/восстановление, undo для hard delete.
- Узлы-метки/проекты в графе, создание связей перетаскиванием между узлами.
- Авторизация, публикация наружу, мобильное приложение.
- Циклы, roadmap, оценки, велосити (запрет проекта).
- Смена визуального стиля (CRT остаётся), новые зависимости/сборщик.

## Further Notes

- Версия: пакет добавляет функциональность обратносовместимо (кроме намеренного изменения контракта DELETE 405→200 — это исправление намеренного запрета, зафиксировано в CHANGELOG). Кандидат — `0.4.0-alpha.1`; подъём согласуется с пользователем отдельно.
- Порядок работ: удаление (бэкенд→UI) → зависимости в drawer → разбивка на модули → граф → бренд/читаемость. Разбивка до графа, чтобы граф сразу лёг в отдельный модуль.
- Автостарт: TUI-плагин OpenCode (`~/.config/opencode/plugins/kanso`, вне репозитория, подключён в `cli.json`) проверяет `/health` при старте TUI и поднимает `serve`, если доска мертва; при выходе TUI гасит свой процесс. Гонка инициализации двух процессов («database is locked») исправлена порядком pragma в store.
- Мульти-агентность (Claude Code, Codex и подобные) — будущее направление вне v0.4: CLI и HTTP уже агент-agnostic (идентичность сессии через флаг/заголовок), OpenCode-специфичны только доставка сообщений в сессию и автостарт через TUI-плагин. Для других агентов потребуются адаптеры доставки и автостарта; контракт доски при этом не меняется.
