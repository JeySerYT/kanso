# Как участвовать в Kanso

Спасибо, что заглянули. Проект небольшой, поэтому правил мало.

## Что нужно

Node.js ≥ 22.5. Зависимостей нет: `npm install` не требуется, `node:sqlite` входит в Node.

```sh
git clone https://github.com/JeySerYT/kanso.git
cd kanso
npm test                        # весь набор
node --test test/store.test.js  # один файл
node bin/kanso.js serve         # доска на http://localhost:7777
```

## Границы проекта

- Без зависимостей, сборщиков, ORM и CSS-препроцессоров. Если без пакета не обойтись — сначала откройте Issue и объясните, почему.
- Источник истины для задач — SQLite, а не markdown-файлы.
- Интерфейс агента — CLI, не MCP: общий процесс не различает сессии, и аренда уезжает в `local`.
- Веб-доска ходит в OpenCode только через `src/opencode-client.js`.

## Где что лежит

```
bin/        вход CLI
src/        хранилище, конфликты, HTTP, CLI, проекты, i18n, клиент OpenCode
web/        статическая доска: HTML, CSS, JS, словари, шрифты
test/       тесты на node:test
docs/       спецификация, редизайн, UX-аудит
```

Тесты пишутся на швах: `openStore()`, `detectConflict()/resolve()`, `createServer()`, `run()`, `discoverRepositories()`, `translator()`. Внутрь этих модулей тесты не лезут. UI проверяется руками в браузере.

## Локализация

Строки живут в `web/locales/ru.json` и `web/locales/en.json`. Их используют и доска, и CLI. Наборы ключей обязаны совпадать — это проверяет `test/i18n.test.js`. Новый текст без ключа не принимается.

## Коммиты

Conventional Commits, императив, до 72 символов в заголовке:

```
fix(cli): не терять аренду при повторном claim

Почему изменение нужно и что оно ломало.
Проверено: npm test.
```

Тело отвечает на «почему», а не пересказывает дифф. Один коммит — одна логическая правка. Ломающее изменение помечается `!` и футером `BREAKING CHANGE:`.

## Pull request

В PR коротко: что меняется, зачем, как проверено. Если менялся интерфейс — приложите скриншот или опишите сценарий. CI должен быть зелёным, `npm test` — проходить локально.

## Версия

`VERSION` — единственный источник истины, `package.json` обязан совпадать. Версию не поднимайте в обычном PR: это делает мейнтейнер при релизе.

## Поведение

Участвуя в проекте, вы соглашаетесь с [кодексом поведения](CODE_OF_CONDUCT.md). Уязвимости не обсуждаются в Issues — для них есть [SECURITY.md](SECURITY.md).
