# Spec v0.4 — deletion, graph, structure, brand, readability

Status: agreed (user decisions recorded below).
Predecessor: `docs/redesign.en.md` (v0.3, dispatcher terminal).

## Problem Statement

1. Tasks cannot really be deleted: DELETE returns 405, "deletion" is the canceled status, junk tasks accumulate forever.
2. No overview of task relationships: `blocked_by` dependencies are only visible as text in the drawer; the big picture of blockers is unseen.
3. Some text in the CRT theme reads poorly (low contrast of secondary text, scanlines/grain noise over content).
4. The user dislikes the logo (kanji 簡) and favicon; the mark is unreadable at 16px.
5. All board logic lives in one file (~1900 lines of JS + ~2400 lines of CSS); the page is overloaded with components, and a graph view cannot be added there without further bloat.

## Solution

- Real task deletion with confirmation: drawer button → dialog → task removed from the database, references in other tasks cleaned up, all tabs updated via SSE.
- New Obsidian-style "Graph" view: canvas force layout, task nodes, dependency edges; a "Board / Graph" view switcher.
- Dependency editor in the drawer so the graph can be populated from the UI.
- Board code split into ES modules in subfolders, CSS into thematic files; no bundler.
- New mark: minimal kanban glyph (three vertical bars of different heights inside a square), shared by logo and favicon.
- Targeted contrast/noise audit and fixes while keeping the CRT style.

## User Stories

1. As a board user, I want to permanently delete a task via a drawer button, so junk does not accumulate in the database.
2. As a user, I want a confirmation dialog showing the task title before deletion, so I do not delete by accident.
3. As a user, I want someone else's actively leased task to be undeletable, so I do not break another session's work.
4. As a user, I want a deleted task to disappear from all open tabs without a reload, so I see the current board.
5. As a user, I want references to a deleted task in other tasks' `blocked_by` removed automatically, so no dangling blockers remain.
6. As a user, I want a task whose blockers were all removed by deletion to move from backlog to todo, so unblocked work is visible.
7. As an agent via CLI, I want a `delete <id> --yes` command to remove tasks programmatically; without `--yes` the command must refuse, so an agent cannot silently delete data.
8. As a user, I want a clear error when deleting a missing or leased task, so I understand what happened.
9. As a user, I want to open the "Graph" view via a header switcher, so I can see the whole map of tasks and blockers.
10. As a user, I want the chosen view to persist across reloads, so I do not switch every time.
11. As a user, I want graph nodes colored by status and sized by priority, so I can read board state at a glance.
12. As a user, I want leased tasks to show a green ring on the graph, so active work is noticeable.
13. As a user, I want arrows from blocker to dependent, so I understand block direction.
14. As a user, I want to click a node and open the task drawer, so I can edit tasks right from the graph.
15. As a user, I want a hover tooltip with id, title and status, so I do not open the drawer just to look.
16. As a user, I want to drag nodes, pan and wheel-zoom the graph, so I can explore large boards.
17. As a user, I want the graph to respect the project filter and search, so I can view one project's map.
18. As a user, I want the graph to update via SSE (create, delete, status change), so the map is live.
19. As a user with prefers-reduced-motion, I want a static graph without continuous animation, so it does not cause discomfort.
20. As a user, I want clear hints on an empty graph and on a graph without edges, so I know what to do next.
21. As a user, I want to edit the "Blocked by" list in the drawer (add/remove tasks), so I can build dependencies without the CLI.
22. As a user, I want self-blocking to be impossible, so no dead self-loops are created.
23. As a user, I want cyclic dependencies rejected with a clear error, so tasks do not hang forever.
24. As a developer, I want board JS in modules under subfolders, so edits are local and diffs short.
25. As a developer, I want CSS split into thematic files, so a component's styles live next to the component.
26. As a developer, I want the split to change no behavior and break no test seams, so the refactor is safe.
27. As a user, I want a new logo and favicon as a strict kanban mark, so the brand is readable and modern.
28. As a user, I want the favicon recognizable at 16px in a browser tab, so I can find the board among dozens of tabs.
29. As a low-vision user, I want secondary text (metadata, counters, hints) to have sufficient contrast, so I can read the board without strain.
30. As a user, I want scanlines/grain not to interfere with reading text, so CRT aesthetics do not hurt usability.
31. As a user, I want an "Effects" toggle to disable scanlines/grain, so I get a clean board when needed.
32. As a RU/EN user, I want all new strings (deletion, graph, dependencies, effects) translated in both languages, so the interface is consistent.
33. As a mobile board user, I want the graph to work on touch screens (pan, pinch-zoom, tap on node), so I can view the map from my phone.
34. As a command palette user, I want "Delete task" and "Open graph" commands, so I can do it from the keyboard.
35. As a user, I want the drawer of a deleted task to close after deletion, so I am not left staring at an empty shell.

## Implementation Decisions

### Deletion (backend)
- New store method `deleteTask(id, { session })`: single transaction; `not_found` refusal; `leased` refusal if another session holds an active (unexpired) lease; own lease is removed with the task.
- Cascades: claims and comments removed via existing FK ON DELETE CASCADE. Threads have no FK to tasks: threads referencing the task (task_a/task_b) are removed by an explicit statement, their messages cascade via the threads→messages FK.
- After deletion: the deleted id is removed from every task's `blocked_by`; backlog tasks with no remaining blockers move to todo (same rule as existing unblockDependents).
- HTTP: `DELETE /api/tasks/:id` → 200 `{ ok: true, id }`; 404 `not_found`; 409 `leased`. The 405 `use_canceled_status` response is removed. SSE event `task.deleted` with `{ id }`.
- CLI: `delete <id> --yes` command; without the flag — an error with a hint. Texts via i18n keys.

### Deletion (web)
- "Delete" button in the drawer (danger zone) → modal confirmation dialog with the task title → DELETE → drawer closes, informational toast without undo (hard delete is irreversible; confirmation is the only guard).
- Delete command in the palette for the currently selected task.

### Dependencies
- PATCH already accepts `blocked_by` — backend unchanged except validation: the store rejects self-reference and cycles (code `cycle`) on create/patch; check is a dependency-graph traversal.
- Drawer: "Blocked by" section — list of current blockers with remove buttons and a task picker (search by id/title, excluding the task itself). Saved via the existing PATCH.

### Graph
- Separate view, "Board / Graph" switcher in `sidebar-head` (above projects); view state — `#board` / `#graph` in the URL hash and `localStorage["kanso.view"]`. Hash wins over localStorage; an unknown value falls back to the board.
- `web/js/graph.js` module + `web/css/graph.css`; Canvas 2D, custom force layout (node repulsion, edge springs, centering), no dependencies. Simulation decays and stops; static layout when the tab is hidden or with reduced-motion (240 steps, 90 for >150 nodes).
- Nodes: color by status (existing palette), radius by priority (p0 largest), green ring on active lease. Edges: directed, arrow blocker → dependent; an edge is highlighted when hovering one of its ends.
- Interactions: node drag (a node stays pinned after dragging), background pan, wheel/pinch zoom in the 0.25–3 range around the cursor, node click → drawer, hover → tooltip (id, status, title). Touch: tap = click, one finger = pan/drag, two = pinch.
- Data: existing `/api/board` + SSE; project filter and search apply to nodes. DPR-aware rendering (cap 2), `ResizeObserver` on the container, `stopLoop()` when the view/tab is hidden.
- Empty states: no tasks under the filter — a "Reset filters" card; tasks but no edges — a hint at the bottom. Keys `graph.*`.
- Access: canvas with `role="application"`, `tabindex="0"` and `aria-describedby` with key hints; arrow keys select a task, Enter opens it, `+`/`−` zoom, `0` fits the graph. The view switcher uses `aria-pressed`, view changes and node selection are announced via live region, statuses have a text legend. One palette command: "Open graph" on the board and "Open board" on the graph; board hotkeys (`n`, `c`, `/`, `?`) keep working in the graph.

### Code structure
- `web/board.js` → ES modules in `web/js/`: entry `main.js`; `core` (state, API, toasts, helpers), `board` (columns and cards), `drag`, `events` (SSE), `toolbar`, `drawer`, `compose`, `palette`, `hotkeys`, `language`, `graph` (Graph view), `effects` (CRT effects toggle). Native ESM, no bundler; `index.html` loads a single entry module.
- `web/board.css` → thematic files in `web/css/`: base, layout, buttons, toolbar, board, dialogs, drawer, overlays, feedback, graph, responsive, loaded via `<link>` in the original cascade order.
- No behavior change; test seams (store/conflicts/http/cli/git/i18n) untouched by the refactor.

### Brand
- The mark: three vertical bars of different heights (kanban columns) inside a square, SVG. In the header — an inline 16×16 SVG with `currentColor` inside the 28×28 `.brand-mark` frame, colored with the palette accent. `web/favicon.svg` — the same drawing on a `#0a0a0a` background with a `#3a3a3a` frame and `#ff2a2a` bars; the three bars stay readable at 16px. The kanji 簡 is removed from the markup (it survives only in this spec and in README as the etymology of the name).

### Readability
- Secondary text contrast: `--faint` raised `#808080` → `#8a8a8a` (5.04:1 on `--surface-2`, 5.34:1 on `--surface-1`), `--text-3` — 6.19:1, `--accent` — 4.65:1, `--text`/`--text-2` — 14.5:1 and 10.3:1. All ≥ 4.5:1, the CRT style is preserved.
- Softer scanlines/grain: scanline alpha `rgba(0,0,0,0.14)` → `0.1`, overall opacity `0.5` → `0.45`, grain `0.05` → `0.04`.
- "Effects" toggle in the sidebar footer: `aria-pressed`, ON/OFF values, state in `localStorage["kanso.effects"]`, on by default. The off mode sets `body.no-effects` and hides the `.crt` layer entirely; the rest of the UI is unchanged.

### Localization
- All new strings as keys in `web/locales/ru.json` and `en.json`; parity caught by the existing test.

## Testing Decisions

- Test only the existing seams from AGENTS.md; no new seams. A good test checks external behavior (codes, contracts, texts), not internals.
- `test/store.test.js`: deleteTask — success, not_found, refusal on another session's active lease, comments/claims/threads cascade, blocked_by cleanup, backlog→todo unblocking, self-reference and cycle rejection.
- `test/http.test.js`: DELETE 200/404/409, SSE `task.deleted` frame, JSON contract.
- `test/cli.test.js`: `delete` requires `--yes`, output/error texts.
- `test/i18n.test.js`: key parity (existing).
- Graph, views, UI deletion, brand, readability — browser verification (Playwright scenarios + manual review), as the project does for UI.
- Prior art: existing test/store.test.js, test/http.test.js, test/cli.test.js.

## Out of Scope

- Trash/restore, undo for hard delete.
- Label/project nodes in the graph, creating edges by dragging between nodes.
- Authorization, public exposure, mobile app.
- Cycles (sprints), roadmap, estimates, velocity (project ban).
- Visual style change (CRT stays), new dependencies/bundler.

## Further Notes

- Version: the package adds backward-compatible functionality (except the intentional DELETE contract change 405→200 — a fix of a deliberate prohibition, recorded in CHANGELOG). Candidate — `0.4.0-alpha.1`; the bump is agreed with the user separately.
- Work order: deletion (backend→UI) → drawer dependencies → module split → graph → brand/readability. Split before graph so the graph lands directly in its own module.
- Autostart: the OpenCode TUI plugin (`~/.config/opencode/plugins/kanso`, outside the repo, wired in `cli.json`) checks `/health` on TUI start and spawns `serve` if the board is dead; on TUI exit it stops its own process. The two-process init race ("database is locked") is fixed by pragma order in the store.
- Multi-agent support (Claude Code, Codex and similar) is a future direction outside v0.4: CLI and HTTP are already agent-agnostic (session identity via flag/header); only message delivery into sessions and autostart via the TUI plugin are OpenCode-specific. Other agents will need delivery and autostart adapters; the board contract stays unchanged.
