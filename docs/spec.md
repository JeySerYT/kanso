# Kanso — спецификация v0.1

Локальная канбан-доска и координация сессий OpenCode через задачи. Статус: `alpha`.

## 1. Цель

Один бэклог на все проекты, где каждая задача может быть захвачена сессией OpenCode на время работы. Сессии видят, кто чем занят, не берут одно и то же и умеют договариваться при пересечении файлов.

## 2. Границы

Входит:

- хранилище задач на SQLite;
- веб-доска с колонками и drag&drop;
- CLI для агента;
- аренда задачи, бронь файлов, зависимости;
- переговоры между сессиями с лимитом и эскалацией;
- автозапуск доски вместе с OpenCode;
- интерфейс на русском и английском с расширением на другие языки.

Не входит: команды и роли, циклы, roadmap, оценки, учёт времени, мобильное приложение, облачная синхронизация.

## 3. Модель данных

```text
tasks
  id            TEXT PK      ANI-15 (префикс проекта + счётчик)
  title         TEXT
  body          TEXT
  project       TEXT          AniVella
  branch        TEXT          ветка git, необязательно
  status        TEXT          backlog | todo | in_progress | review | done | canceled
  priority      INTEGER      0..4, 0 — самый высокий
  position      REAL          порядок внутри колонки
  labels        TEXT          JSON-массив имён меток
  blocked_by    TEXT          JSON-массив id
  created_at    TEXT          ISO 8601 UTC
  updated_at    TEXT
  closed_at     TEXT

labels
  name          TEXT PK       до 32 символов
  color         TEXT          #rrggbb
  created_at    TEXT          ISO 8601 UTC

claims
  task_id       TEXT PK
  session_id    TEXT
  cwd           TEXT
  touched_paths TEXT         JSON-массив
  claimed_at    TEXT
  lease_until   TEXT
  heartbeat_at  TEXT

comments
  id            INTEGER PK
  task_id       TEXT
  session_id    TEXT
  kind          TEXT         note | handoff | decision
  body          TEXT
  created_at    TEXT

threads
  id            TEXT PK
  task_a        TEXT
  task_b        TEXT
  path          TEXT
  state         TEXT         asked | agreed | needs_decision | closed
  created_at    TEXT

messages
  id            INTEGER PK
  thread_id     TEXT
  from_session  TEXT
  proposal      TEXT         take-now | wait | split | escalate
  body          TEXT
  created_at    TEXT

sessions
  id            TEXT PK
  cwd           TEXT
  agent         TEXT
  started_at    TEXT
  last_seen_at  TEXT
```

Инварианты:

- у задачи не больше одного активного захвата;
- захват невозможен, если `lease_until` в прошлом и не продлён — аренда переходит новому владельцу;
- задача с незакрытыми `blocked_by` не захватывается;
- в треде не больше двух сообщений от каждой стороны;
- метка существует в реестре `labels`, повторное создание не меняет её цвет;
- приоритет вне `0..4` отклоняется с `priority_out_of_range`.

Проект — это имя git-репозитория (basename каталога). Ветка — необязательное поле задачи: список доступных веток берётся из репозитория проекта. Репозитории ищутся в `KANSO_ROOTS` (разделитель — `path.delimiter`, на Linux `:`), по умолчанию — типовые папки вроде `~/Документы/Project's` и `~/Projects`. Глубина поиска 4, служебные каталоги (`node_modules`, `.git`, `dist`, `build`, `vendor`, `.worktrees`) пропускаются. Результат кэшируется на 15 секунд, `GET /api/projects?refresh=1` сбрасывает кэш.

## 4. Протокол координации

1. `claim(task)` — атомарный захват. Если файлы пересекаются с активным захватом другой сессии, возвращается конфликт.
2. `touch(task, paths)` — объявление файлов. Точное совпадение пути — отказ. Пересечение по каталогу — тред переговоров.
3. Переговоры: обеим сессиям уходит по одному сообщению через `session.prompt`. Ответ — `take-now`, `wait`, `split`, `escalate`.
   - один `wait` → второй получает бронь;
   - оба `split` → брони по непересекающимся путям;
   - оба `take-now` или `escalate` → `needs_decision`, вопрос человеку.
4. `release(task, note)` — снять захват, оставить комментарий с состоянием: ветка, что сделано, следующий шаг.
5. `done(task, note)` — закрыть, разблокировать зависимые.

Просроченная аренда: задача остаётся `in_progress`, но помечается `stale`; следующая сессия может забрать её через `claim`.

## 5. HTTP-контракт

```text
GET    /api/board                  доска: задачи, захваты, треды, метки, версия
GET    /api/projects               git-репозитории, текущая и локальные ветки
GET    /api/labels                 реестр меток
POST   /api/labels                 создать метку (name, color)
GET    /api/tasks                  список с фильтрами project/status
POST   /api/tasks                  создать (title, project, branch, priority, labels)
GET    /api/tasks/:id              карточка с комментариями и тредами
PATCH  /api/tasks/:id              заголовок, тело, приоритет, метки, проект, ветка
POST   /api/tasks/:id/move         статус и позиция (drag&drop)
POST   /api/tasks/:id/claim        захват
POST   /api/tasks/:id/touch        объявить файлы
POST   /api/tasks/:id/release      освободить
POST   /api/tasks/:id/done         закрыть
POST   /api/tasks/:id/comment      комментарий
GET    /api/threads                треды переговоров
POST   /api/threads/:id/reply      ответ в треде
GET    /api/events                 SSE: изменения задач и конфликтов
GET    /health                     версия и статус
```

Ошибки: `400` — невалидный ввод, `404` — нет задачи, `409` — конфликт захвата или зависимость, `423` — аренда занята другой сессией.

## 6. Интерфейс для агента

CLI, а не MCP: идентичность сессии приходит из окружения shell (`OPENCODE_SESSION_ID`), которое OpenCode выставляет для каждой сессии. MCP-процесс общий на проект и вызывающую сессию не различает, поэтому от него отказались.

```text
kanso list [--project P] [--status S]          очередь
kanso new "title" [--project P] [--branch B]   создать
kanso get ANI-15                               карточка + комментарии
kanso claim ANI-15 [--paths a,b]               захват с бронью файлов
kanso touch ANI-15 a,b                         объявить файлы
kanso move ANI-15 in_progress                  сменить статус
kanso comment ANI-15 "text"                    комментарий
kanso release ANI-15 --note "..."              освободить
kanso done ANI-15 --note "..."                 закрыть
kanso threads [--state asked]                  треды переговоров
kanso reply THREAD-1 wait                      ответить
kanso whoami                                   сессия, cwd, текущая задача
kanso serve [--port 7777] [--db path] [--roots a,b]   доска
```

Приоритеты — `p0` (критический) … `p4` (когда-нибудь), по умолчанию `p2`.

Команды печатают короткий текст для агента: что произошло, кто владелец, что делать дальше. Ошибка — не стектрейс, а строка с кодом (`409` — занято, `423` — аренда чужая). Язык вывода выбирается из `KANSO_LANG`, затем `LC_ALL`, `LC_MESSAGES`, `LANG`; поддерживаются `ru` и `en`, по умолчанию `ru`.

## 7. Веб-доска

Навигация — в сайдбаре, не в верхней панели: бренд, «Новая задача», поиск, проекты с количеством задач, статус подключения, версия и выбор языка. Колонки: Backlog, Todo, In Progress, Review, Done; «Отменено» показывается при наличии отменённых задач. Горизонтальная прокрутка доски работает колесиком мыши и `Shift` + колесико.

Карточка: ID, заголовок, проект, ветка, приоритет `p0–p4` (меняется селектом прямо на карточке), метки с цветами (клик по метке ставит фильтр), владелец и обратный отсчёт аренды `T-ММ:СС` с тиком раз в секунду; просроченная аренда подсвечивается hazard-полосами. Двойной клик по заголовку переименовывает задачу инлайн. Drawer: тело, мета-сетка (создана, обновлена, ветка, владелец, аренда, файлы, блокеры), правка приоритета и меток, комментарии, треды переговоров, смена статуса, кнопка «Готово» и «Отменить задачу» с возвратом через тост.

Тулбар над доской: фильтры по метке и приоритету, тумблер «В аренде», сортировка (вручную / по приоритету / по обновлению / по созданию), плотность COMPACT/COMFORT, «Меню» и справка по хоткеям. Сортировка и плотность сохраняются в `localStorage`. Командная палитра `Ctrl/Cmd+K`: создание задачи, поиск, переход к проекту, фильтр по метке, сортировка, плотность, язык, сброс фильтров. Хоткеи: `/` поиск, `C`/`N` новая задача, `?` справка, стрелки — фокус по карточкам, `Enter` — drawer, `1–5` — статус карточки в фокусе.

Форма создания: заголовок, проект из найденных git-репозиториев или «Новый проект…», ветка выбранного проекта или «Другая ветка…», приоритет, описание и метки. Метки выбираются кликом из общего реестра; новая метка создаётся тут же и получает цвет из палитры.

Drag&drop меняет `status` и порядок: карточка следует за курсором отдельным слоем, исходная остаётся приглушённой, счётчики и пустые состояния обновляются из состояния. То же доступно с клавиатуры (`Alt` + стрелки), фокус остаётся на ручке карточки.

Стиль: «диспетчерская» — CRT-терминал (industrial brutalism). Geist Mono для данных и навигации, Geist Sans для заголовков задач; скруглений нет, рамки 1px, единственный акцент — аварийный красный, терминальный зелёный только у индикатора аренды; сканлайны и зерно фиксированным overlay. Нативные `select` и `option` принудительно тёмные. Токены и решения — в `docs/redesign.md`.

SSE-события приходят на любое изменение базы. Сервер сравнивает `PRAGMA data_version` и рассылает `board.synced`, поэтому правки из CLI в другом процессе видны без перезагрузки.

## 8. Локализация

Словари — обычные JSON-файлы `web/locales/<lang>.json`. Один и тот же набор ключей используют веб-доска (fetch) и Node/CLI (`readFileSync`), поэтому переводы не дублируются. Ключи плоские и сгруппированы префиксом: `status.*`, `priority.*`, `compose.*`, `drawer.*`, `error.*`, `cli.*`.

- Поддерживаемые языки перечислены в `web/i18n.js` и `src/i18n.js`; сейчас `ru` и `en`.
- Веб: язык берётся из `localStorage.kanso.lang`, иначе из `navigator.languages`, иначе `ru`; переключатель — в сайдбаре.
- CLI: `KANSO_LANG` → `LC_ALL` → `LC_MESSAGES` → `LANG` → `ru`.
- Неизвестный ключ возвращается как есть, отсутствующий в языке — берётся из `ru`.
- Параметры подставляются через `{name}`.
- Тест `test/i18n.test.js` проверяет паритет ключей `ru` и `en`, поэтому новый язык обязан покрыть весь набор.

Чтобы добавить язык: скопировать `web/locales/en.json` в `<lang>.json`, перевести значения, добавить код в списки `SUPPORTED`/`SUPPORTED_LOCALES` и `<option>` переключателя, затем прогнать тесты.

## 9. Автозапуск

Плагин `~/.config/opencode/plugins/kanso/tui.tsx` подключён в `~/.config/opencode/cli.json`. В `setup(ctx)` он проверяет `GET /health`; если доска не отвечает, запускает `node bin/kanso.js serve` отдельным процессом и останавливает его при выходе из TUI. Плагин идемпотентен: второй запуск ничего не делает. Пути переопределяются через `KANSO_DIR`, `KANSO_URL`, `KANSO_NODE`.

## 10. Критерии приёмки

- 100 параллельных `claim` одной задачи → ровно один владелец.
- `kill -9` владельца → задача освобождается не позже 15 минут.
- Пересечение по файлу: обе сессии получают по одному сообщению, третье не отправляется.
- Тупик → `needs_decision`, карточка помечена, человек получает вопрос.
- Статус, изменённый на доске, виден агенту при следующем запросе и наоборот.
- Изменение из CLI появляется на открытой доске без перезагрузки.
- `GET /health` отдаёт версию из `VERSION`.
- Приоритет `p5` и метка длиннее 32 символов отклоняются.
- Перенос карточки обновляет счётчики, пустое состояние и сохраняется на сервере.
- `Alt` + стрелки перемещают карточку и не теряют фокус.
- Переключение `ru`/`en` меняет весь интерфейс и сохраняется после перезагрузки.
- Наборы ключей `ru` и `en` совпадают, неизвестный ключ не ломает вывод.
