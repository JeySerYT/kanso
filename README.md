# Kanso

[![CI](https://github.com/JeySerYT/kanso/actions/workflows/ci.yml/badge.svg)](https://github.com/JeySerYT/kanso/actions/workflows/ci.yml)

[![License](https://img.shields.io/github/license/JeySerYT/kanso?style=flat-square)](LICENSE)

Локальная канбан-доска для нескольких сессий OpenCode: задачи в одном SQLite-файле, аренда задачи на время работы и переговоры при пересечении файлов. Веб-доска на `localhost` и CLI для агента, без облака и внешних сервисов.

Название — от 簡素 (*kanso*, «простота»): коротко, набирается одной рукой, не конфликтует с Linear и Jira.

## Зачем

- Задачи живут в одном месте для всех проектов, а не в семи папках.
- Сессия берёт задачу в работу через аренду: две сессии не схватят одно и то же.
- При пересечении по файлам сессии договариваются сами, тупик уходит человеку.
- Доска открывается в браузере, данные не покидают машину.
- Интерфейс и CLI говорят на русском и английском; новый язык добавляется одним JSON-файлом.

## Установка

Нужен Node.js ≥ 22.5. Зависимостей нет, `npm install` не требуется.

```sh
git clone https://github.com/JeySerYT/kanso.git
cd kanso
node bin/kanso.js serve
```

Доска откроется на <http://localhost:7777>. Чтобы вызывать `kanso` без полного пути, выполните `npm link` в папке репозитория.

## Быстрый старт

```sh
kanso serve                                                       # доска
kanso new "Починить экспорт" --project AniVella --status todo      # задача в очередь
kanso next --paths src/export.js                                   # взять верхнюю
kanso comment ANI-1 "Причина найдена: пустой фильтр"               # заметка
kanso done ANI-1 --note "Экспорт не падает на пустом фильтре"      # закрыть
```

`kanso list` показывает очередь, `kanso --help` — все команды и цикл статусов, `kanso help <команда>` — справку по одной команде.

## Команды

Идентичность сессии берётся из `OPENCODE_SESSION_ID`, который OpenCode выставляет для каждой сессии. Если переменной нет, используется `local`; можно задать явно через `--session`.

```sh
kanso --help                                команды, флаги и цикл статусов
kanso list [--project P] [--status S]       очередь
kanso next [--project P] [--paths a,b]      взять верхнюю задачу из todo
kanso new "title" [--project P] [--branch B] [--label a,b] [--priority 0..4] [--status todo] [--body "..."]
kanso get ANI-1                             карточка, владелец, треды
kanso claim ANI-1 [--paths src/a.js,b]      захват с бронью файлов
kanso touch ANI-1 src/a.js src/b.js         объявить файлы
kanso move ANI-1 in_progress                сменить статус
kanso comment ANI-1 "text"                  комментарий
kanso release ANI-1 --note "state"          освободить, оставить состояние
kanso done ANI-1 --note "result"            закрыть
kanso delete ANI-1 --yes                    удалить навсегда (без --yes отказывает)
kanso threads [--state asked]               треды переговоров
kanso reply THR-1 take-now|wait|split|escalate [text]
kanso whoami                                сессия, cwd, текущая задача
kanso serve [--port 7777] [--host 0.0.0.0] [--db path] [--roots a,b]   доска
```

Команды печатают короткий текст для агента: что произошло, кто владелец, что делать дальше. Ошибка — строка с кодом (`locked`, `blocked`, `path_locked`, `needs_agreement`), а не стектрейс; полный стек выводится при `KANSO_DEBUG=1`.

## Координация

1. `claim` — атомарный захват задачи и аренда на 15 минут. Аренда продлевается вызовами `touch`, `comment`, `move`.
2. `touch` объявляет файлы. Точное совпадение пути — отказ; пересечение по каталогу открывает тред переговоров.
3. В треде не больше двух сообщений с каждой стороны. `wait` уступает, два `split` делят пути, два `take-now` или `escalate` → `needs_decision` для человека.
4. `release` и `done` снимают аренду; `done` разблокирует зависимые задачи.
5. `delete` удаляет задачу навсегда вместе с комментариями и тредами; чужая активная аренда запрещает удаление. Ссылки `blocked_by` у других задач чистятся, полностью разблокированный backlog переезжает в todo. В вебе — кнопка «Удалить навсегда» с подтверждением.

## Веб-доска

Навигация — в сайдбаре: бренд, «Новая задача», поиск, проекты с количеством задач, статус подключения, версия и переключатель языка. Над доской — тулбар: фильтры по метке и приоритету, тумблер «В аренде», сортировка (вручную / по приоритету / по обновлению / по созданию), плотность COMPACT/COMFORT, «Меню» и справка по хоткеям. Сортировка и плотность сохраняются между сессиями.

Пять колонок — «Бэклог», «К работе», «В работе», «Ревью», «Готово»; «Отменено» появляется, когда есть отменённые задачи. Доска прокручивается по горизонтали колесиком мыши.

Карточка показывает проект, ветку, приоритет `p0–p4` (меняется прямо на карточке), цветные метки (клик по метке ставит фильтр), владельца и обратный отсчёт аренды `T-ММ:СС`; просроченная аренда подсвечивается. Двойной клик по заголовку переименовывает задачу инлайн. Карточки перетаскиваются мышью и с клавиатуры (`Alt` + стрелки); стрелки без `Alt` двигают фокус, `1–5` меняют статус карточки в фокусе, `Enter` открывает drawer.

Командная палитра `Ctrl/Cmd+K` умеет создавать задачи, искать, переходить к проектам, фильтровать, сортировать и менять язык; `/` — поиск, `C` — новая задача, `?` — шпаргалка. Drawer показывает тело, мета-сетку, правку приоритета и меток, комментарии, треды и аренду; «Отменить задачу» возвращает задачу через тост с undo.

Стиль доски — «диспетчерская»: CRT-терминал, моноширинные данные, нулевые скругления, один красный акцент и зелёный индикатор аренды. Токены и решения редизайна — в `docs/redesign.md`.

При создании задачи проект выбирается из найденных git-репозиториев, ветка — из веток выбранного проекта. Можно ввести новый проект и другую ветку вручную. Метки выбираются кликом из общего реестра; новая метка создаётся тут же.

Интерфейс обновляется через SSE. Сервер следит за `PRAGMA data_version`, поэтому изменения из CLI в другом процессе тоже появляются на доске без перезагрузки.

## Проекты и ветки

Проект — это имя git-репозитория. Kanso ищет репозитории в `KANSO_ROOTS` (разделитель — `:` на Linux) на глубине 4 и пропускает `node_modules`, `.git`, `dist`, `build`, `vendor`, `.worktrees`. Без переменной используются типовые папки вроде `~/Документы/Project's`, `~/Projects`, `~/Developer`. Список кэшируется на 15 секунд; `?refresh=1` сбрасывает кэш.

Ветка необязательна: задача может жить без неё. Текущая ветка репозитория помечается `*` в списке.

## Локализация

Словари лежат в `web/locales/ru.json` и `web/locales/en.json` и используются одновременно веб-доской и CLI. Язык интерфейса хранится в `localStorage.kanso.lang`; CLI берёт язык из `KANSO_LANG`, `LC_ALL`, `LC_MESSAGES` или `LANG`, иначе `ru`.

Чтобы добавить язык, скопируйте `en.json`, переведите значения, добавьте код в `SUPPORTED` в `web/i18n.js` и `src/i18n.js`, добавьте пункт в переключатель и прогоните `npm test`: тест проверяет, что наборы ключей совпадают.

## Конфигурация

| Переменная | Что задаёт |
|---|---|
| `KANSO_DB` | путь к SQLite-файлу вместо `~/.local/share/kanso/board.db` |
| `KANSO_ROOTS` | корни поиска репозиториев, разделитель `:` |
| `KANSO_LANG` | язык CLI: `ru` или `en` |
| `KANSO_PORT` / `KANSO_HOST` | адрес доски для `kanso serve` |
| `OPENCODE_SESSION_ID` | идентичность сессии для аренды |
| `KANSO_DEBUG` | `1` — печатать стектрейс ошибки CLI |

База `~/.local/share/kanso/board.db` работает в режиме WAL с `busy_timeout` 5 секунд. Бэкап — копия файла.

## Разработка

```sh
npm test                        # весь набор
node --test test/store.test.js  # один файл
npm start                       # доска
```

```
bin/        CLI-вход
src/        хранилище, конфликты, HTTP, CLI, git-проекты, i18n, клиент OpenCode
web/        статическая доска: HTML, CSS, JS, словари locales/, шрифты Geist
test/       тесты (node:test)
docs/       спецификация и заметки по дизайну
```

`VERSION` — источник истины для версии. `package.json` обязан совпадать, это проверяет тест. Формат — `X.Y.Z` плюс стадия `alpha` / `beta` / `release`.
