# Kanso

Локальная канбан-доска и координация сессий OpenCode через задачи: один SQLite-файл, веб-доска на `localhost`, CLI для агента.

Название — от 簡素 (*kanso*, «простота»): коротко, набирается одной рукой, не конфликтует с Linear и Jira.

## Зачем

- Задачи живут в одном месте для всех проектов, а не в семи папках.
- Сессия берёт задачу в работу через аренду: две сессии не схватят одно и то же.
- При пересечении по файлам сессии договариваются сами, тупик уходит человеку.
- Доска открывается в браузере, данные не покидают машину.

## Быстрый старт

```sh
npm test                          # тесты
node bin/kanso.js serve           # доска на http://localhost:7777
node bin/kanso.js list            # задачи в терминале
node bin/kanso.js new "Заголовок" --project AniVella
```

`npm install` не нужен: зависимостей нет.

## Работа агента

Идентичность сессии берётся из `OPENCODE_SESSION_ID`, который OpenCode выставляет для каждой сессии. Если переменной нет, используется `local`.

В примерах `kanso` — это `node bin/kanso.js`. Можно сделать alias или `npm link`.

```sh
kanso list [--project P] [--status S]       очередь
kanso new "title" [--project P] [--label a,b] [--priority 0..3] [--body "..."]
kanso get ANI-1                             карточка, владелец, треды
kanso claim ANI-1 [--paths src/a.js,b]      захват с бронью файлов
kanso touch ANI-1 src/a.js src/b.js         объявить файлы
kanso move ANI-1 in_progress                сменить статус
kanso comment ANI-1 "text"                  комментарий
kanso release ANI-1 --note "state"          освободить, оставить состояние
kanso done ANI-1 --note "result"            закрыть
kanso threads [--state asked]               треды переговоров
kanso reply THR-1 take-now|wait|split|escalate [text]
kanso whoami                                сессия, cwd, текущая задача
kanso serve [--port 7777] [--db path]       доска
```

Команды печатают короткий текст для агента: что произошло, кто владелец, что делать дальше. Ошибка — строка с кодом (`locked`, `blocked`, `path_locked`, `needs_agreement`), а не стектрейс.

## Координация

1. `claim` — атомарный захват задачи и аренда на 15 минут. Аренда продлевается вызовами `touch`, `comment`, `move`.
2. `touch` объявляет файлы. Точное совпадение пути — отказ; пересечение по каталогу открывает тред переговоров.
3. В треде не больше двух сообщений с каждой стороны. `wait` уступает, два `split` делят пути, два `take-now` или `escalate` → `needs_decision` для человека.
4. `release` и `done` снимают аренду; `done` разблокирует зависимые задачи.

## Веб-доска

Пять колонок — «Бэклог», «К работе», «В работе», «Ревью», «Готово»; «Отменено» появляется, когда есть отменённые задачи. Карточки перетаскиваются мышью и с клавиатуры (`Alt` + стрелки). Drawer показывает тело, комментарии, треды и аренду.

Интерфейс обновляется через SSE. Сервер следит за `PRAGMA data_version`, поэтому изменения из CLI в другом процессе тоже появляются на доске без перезагрузки.

## Автозапуск

Плагин `~/.config/opencode/plugins/kanso/tui.tsx` подключён в `~/.config/opencode/cli.json`. При старте TUI он проверяет `/health`; если доска не отвечает, запускает `node bin/kanso.js serve` и останавливает его при выходе. Второй экземпляр ничего не запускает.

Переменные окружения: `KANSO_DIR` — папка проекта, `KANSO_URL` — адрес доски, `KANSO_NODE` — путь к Node.

## Данные

`~/.local/share/kanso/board.db` — SQLite в режиме WAL, `busy_timeout` 5 секунд. Путь переопределяется через `KANSO_DB` или `--db`. Бэкап — копия файла.

## Структура

```
bin/        CLI-вход
src/        хранилище, конфликты, HTTP, CLI, клиент OpenCode
web/        статическая доска: HTML, CSS, JS, шрифты Geist
test/       тесты (node:test)
docs/       спецификация
```

## Версия

`VERSION` — источник истины. `package.json` обязан совпадать, это проверяет тест. Формат — `X.Y.Z` плюс стадия `alpha` / `beta` / `release`.
