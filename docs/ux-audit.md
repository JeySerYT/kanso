# UX-аудит Kanso (v0.4.0-alpha.1)

Дата: 2026-11-22. Метод: ручной прогон сценариев в браузере (Playwright, отдельная БД и сервер на порту 7802) + чтение кода по правилам [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines).

Проверено в браузере: первый запуск, создание задачи, поиск, фильтры, drawer, блокировки, удаление, граф, палитра, справка, мобильный 390×844, сбой `/api/board`, медленная сеть.

Не проверено: производительность графа на 200+ задачах (оценка кода), реальный скринридер, тач-жесты на устройстве, Safari/Firefox.

## Что уже работает хорошо

- Пустая доска — онбординг с CTA, а не пустые колонки; `Enter` в названии создаёт задачу, `Escape` закрывает диалог, пустой заголовок не отправляется.
- Переключение «Доска / Граф» в один клик, состояние в hash и localStorage; граф читается: узлы по статусу, кольцо аренды, направленные рёбра, легенда, «Вписать», клавиатура, скринридер-подписи.
- Удаление: подтверждение с текстом «безвозвратно, вместе с комментариями и переговорами», кнопка «Оставить» рядом.
- Enter/клик по карточке открывает drawer за ~385 мс (задержка на dblclick), форма создания не сбрасывает выбранный «новый проект» при фоновой загрузке.
- Хоткеи доски (`n`, `c`, `/`, `?`, `Ctrl+K`) работают в обоих видах; палитра и справка открываются.

## Сценарии: где пользователь спотыкается

### 1. Первый запуск и загрузка
- Пока грузится `/api/board`, рабочая область пустая: ни колонок, ни скелетона, ни «Загрузка…». На медленной сети (1.2 с задержки) — мёртвый чёрный экран (`ux-loading.png`).
- Фокус после создания первой задачи падает в `body`: непонятно, где продолжать, видна только карточка и тост.
- На пустой доске кнопка «Граф» disabled без подсказки, почему.

### 2. Создание задачи
- 3 действия: «Новая задача» → ввод → `Enter`. Это хорошо.
- Статус не виден: «+» в колонке создаёт задачу в этой колонке, но в диалоге нет ни поля статуса, ни подписи «создастся в „Ревью“».
- Ошибка пустого названия — нативный браузерный пузырь, без inline-текста и `aria-invalid`.
- Нет `maxlength` у заголовка (карточка обрезает по 3 строкам, полный текст не прочитать: `title` карточки — подсказка про переименование).

### 3. Поиск и фильтры
- **Поиск не принимает пробелы**: при вводе «экспорт csv» в поле остаётся `экспортcsv`, карточек 0. Причина: `state.query = search.value.trim()` + запись обратно в поле (`main.js:117`, `board.js:82`). Многословный поиск не работает вообще.
- Фильтры и поиск не попадают в URL и не переживают перезагрузку (в localStorage только сортировка, плотность, вид).
- Нет счётчика «найдено N из M»; пустой результат — четыре колонки с «Ничего не найдено» и «Сброс» в тулбаре (`ux-no-results.png`).

### 4. Drawer и комментарии
- **Черновик комментария стирается** при любом соседнем действии: набрал текст → сменил статус/приоритет/метку/блокировку → поле пустое. Причина: `renderDrawer` вызывает `commentForm.reset()` (`drawer.js:156`), а мутации перезапускают `openTask`.
- Футер: «Статус [селект]», «Удалить навсегда», «Отменить задачу», «Готово ✓». «Готово» — это перевод в `done`, но читается как «закрыть окно», и стоит вплотную к двум опасным кнопкам.
- Чипы блокировок обрезаны («Клавиатурная навигация по г…»), не кликабельны — перейти к блокирующей задаче нельзя.
- Список для добавления блокировки пуст до ввода, максимум 6 результатов, без `aria-expanded` и live-объявления; `Enter` ничего не делает.
- Подтверждение удаления: фокус не на «Оставить» (уходит в `body`), у диалога нет `aria-describedby` на текст последствий.

### 5. Блокировки на доске
- Задача с `blocked_by` выглядит на доске как обычная: ни бейджа, ни счётчика, ни приглушения. При этом `claim` отклоняется с кодом `blocked`. Пользователь узнаёт о блокировке только из drawer или из ошибки агента.
- Связь видна только в графе и в drawer.

### 6. Удаление
- 3 шага: карточка → «Удалить навсегда» → «Удалить». Подтверждение понятное.
- В палитре команда удаления появляется только при открытом drawer — из палитры задачу не удалить.

### 7. Граф
- 1 клик на переключение, вид запоминается. Узлы подписаны только `id` (KAN-2), заголовки — в тултипе. На большом графе приходится водить мышью.
- На пустой доске переключатель disabled без объяснения; на графе из одной задачи нет подсказки, что связи появятся после добавления блокировок (есть общая подсказка внизу).

### 8. Сбой сети
- При недоступном `/api/board` показывается тост «Доска недоступна…» на ~4 с, затем рабочая область пустая, индикатор связи при этом говорит «НА СВЯЗИ» (SSE подключён).
- Любое действие (поиск, клик) перерисовывает доску и показывает **онбординг «Задачи начинаются здесь»** — выглядит как «все задачи пропали». Восстановления без перезагрузки нет, кнопки «Повторить» нет (`ux-offline.png`).

### 9. Мобильный (390×844)
- Сайдбар занимает ~40 % высоты (проекты, язык, эффекты), тулбар — 114 px, доске остаётся ~500 px.
- Подписи фильтров скрыты (`responsive.css:98`): остаются три селекта «любой», «любой», «вручную» без контекста и без доступных имён (`aria-label` нет). Для скринридера это три поля без названия.
- Лента проектов прокручивается горизонтально без индикации, «Kanso [6]» обрезан у края.
- Тост смещён вправо от центра (анимация `rise` перебивает `translateX(-50%)`, `feedback.css:19`); на узком экране широкий тост может уйти за край.
- Drawer на весь экран, футер не переполняется — здесь порядок.

### 10. Доступность
- Чип метки на карточке — `<span>` с обработчиком: фильтр по метке недоступен с клавиатуры (`board.js:301`).
- Поле «Новая метка» — только placeholder, без `<label>`/`aria-label` (`index.html:322`).
- Мобильные селекты фильтров без доступных имён (см. выше).
- Элементы палитры — `li` без собственного фокуса; клавиатура работает только через поле ввода (приемлемо, но нестандартно).
- `role="toolbar"` у тулбара без roving-навигации стрелками.
- Тост и live-region дублируют одно и то же объявление.

## Что добавить: приоритеты

### P0 — «надёжность и nothing lost» (один пакет, без новых экранов)

1. **Поиск и фильтры**: не обрезать пробелы при вводе, многословный поиск (совпадение по всем словам), счётчик «N из M», крестик очистки, состояние `?q=&label=&project=&priority=&leased=` в URL и восстановление при загрузке.
2. **Черновики**: не сбрасывать комментарий при мутациях drawer (хранить по id задачи), предупреждать при закрытии compose/drawer с несохранённым текстом, сохранять черновик при смене языка.
3. **Честные состояния**: скелетон колонок при первой загрузке, панель ошибки с кнопкой «Повторить» и сохранением последних данных, не показывать онбординг при ошибке, индикатор связи отражает реальное состояние API.
4. **Доступность-минимум**: метки-чипы → `<button>`, label для поля метки, `aria-label` мобильным фильтрам, фокус на «Оставить» в подтверждении удаления, `aria-describedby` с последствиями.
5. **Тосты**: починить центрирование (анимировать только `translateY` через `translate` или обёртку), `env(safe-area-inset-bottom)`, не перекрывать футер drawer.

### P1 — заметная польза в ежедневной работе

6. **Блокировки на доске**: бейдж «заблокировано N» на карточке, приглушение/пунктир, переход к блокеру из drawer, объяснение при попытке взять задачу.
7. **Палитра ищет задачи**: ввод в `Ctrl+K` показывает задачи (id, заголовок, статус, проект) выше команд, `Enter` открывает drawer, `Ctrl+Enter` берёт в работу.
8. **Быстрое добавление в колонку**: поле «+ задача» в шапке колонки, `Enter` создаёт в этом статусе — 2 действия вместо диалога; диалог остаётся для подробного ввода.
9. **Drawer: ясные действия**: «Завершить» вместо «Готово», статус-селект в шапке, опасные действия — в меню «⋯», а не рядом с основным.
10. **URL задачи**: `#task/KAN-12` открывает drawer, hash обновляется при открытии/закрытии — ссылки на задачу из терминала и чата.

### P2 — на будущее

11. **История задачи**: лента статусов, аренды, правок (сейчас только комментарии) — полезно и человеку, и агенту.
12. **Граф**: подписи заголовков при зуме, фильтр по статусу, кластеры по проекту, клик по ребру с объяснением связи.
13. **Мобильный режим**: сворачиваемый сайдбар, табы колонок, тач-таргеты 44 px, тост в safe-area.
14. **Экспорт**: доска в JSON/Markdown для бэкапа и отчёта.
15. **SSE-подсветка**: короткая подсветка изменившихся карточек и «N новых скрыто фильтром».

## Рекомендация

Начать с P0 одним пакетом «надёжность»: он убирает потерю текста, ложное «нет задач» и неработающий многословный поиск — то, что бьёт по доверию к доске. P1 (блокировки на карточке и поиск задач в палитре) — следующим пакетом, он меняет ежедневные сценарии.
